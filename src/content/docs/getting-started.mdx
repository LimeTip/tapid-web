# Getting started

Tapid is a JavaScript and TypeScript package manager written in Rust. The current client is a limited development slice, not a production-ready replacement for npm or pnpm.

The useful distinction is simple: the CLI already supports deterministic local installation and lockfile replay, while broader online npm compatibility, publishing, evidence-aware policy, and agent integrations remain planned or incomplete.

## Try the implemented path

The repository contains a consumer fixture that exercises the current install and run behavior without depending on a live registry.

```bash
cargo build -p tapid --locked
export GITHUB_ENV="$(mktemp)"
node tests/fixtures/create_consumer_project.js
. "$GITHUB_ENV"
export TAPID_FIXTURE=1
target/debug/tapid install --offline --frozen --project-dir "$TAPID_FIXTURE_PROJECT"
target/debug/tapid run --project-dir "$TAPID_FIXTURE_PROJECT" test -- forwarded 0
```

A local macOS run produced:

```text
Replayed lockfile: 0 package(s)
Verified: node_modules created; dependency lifecycle marker absent.
```

The fixture checks managed `node_modules`, root-script execution, argument forwarding, child exit-code propagation, executable metadata, and suppression of the dependency lifecycle marker. This is evidence for the fixture path only, not a claim that general npm installation is production-ready.

## What the current client answers

For the implemented path, Tapid can answer:

- Can this project replay its existing lockfile without network access?
- Does the lockfile's manifest and store content validate before activation?
- Were managed `node_modules` files created?
- Can an explicit root script run with forwarded arguments?
- Does the child process exit code return to the caller?
- Were dependency lifecycle scripts suppressed during install?

## What is not implemented yet

The current client does not provide complete npm range compatibility, aliases, tags, git/file/workspace specs, peer resolution, workspaces, private-registry authentication, package publishing, an audit command, an agent runner, a sandbox, or process capability enforcement.

The website and documentation describe those areas only as planned or future direction. See [Commands](/docs/commands/) for the current command surface and the [roadmap](/roadmap/) for sequencing.

Read [Package identity](/docs/concepts/package-identity/) to understand why a name and version range are not enough to identify an artifact.
