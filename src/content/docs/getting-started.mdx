tapid is a JavaScript and TypeScript package manager written in Rust. Version 0.0.7 can resolve and install a deliberately limited npm-compatible dependency graph. It is not yet a drop-in replacement for npm or pnpm, and no asset-backed stable release is currently available.

## Build the alpha from source

Source installation from the current main branch is the supported contributor-development path on macOS and Linux. Download and inspect the mutable installer before executing it:

```bash
installer="$(mktemp)"
curl -fsSL https://raw.githubusercontent.com/LimeTip/tapid/main/scripts/install.sh -o "$installer"
less "$installer"
sh "$installer" --source-ref main
rm -f "$installer"
```

On Windows PowerShell, download and inspect the installer before running it:

```powershell
$installer = Join-Path $env:TEMP "tapid-install.ps1"
Invoke-WebRequest https://raw.githubusercontent.com/LimeTip/tapid/main/scripts/install.ps1 -OutFile $installer
Get-Content $installer
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installer -SourceRef main
Remove-Item $installer
```

These commands build tapid from source. They do not install a signed stable release. The no-argument public installer remains unavailable until signed release metadata and platform archives are published and verified.

Open a new terminal if the installer reports that it updated your user-level `PATH`, then confirm the binary is available:

```text
tapid --version
```

## Install a package

Create a project and install one supported package:

```bash
mkdir demo
cd demo
tapid init
tapid i is-char
```

`tapid i <package>` is an alias for `tapid install <package>`. By default, the command writes the dependency to `package.json`, resolves supported transitive dependencies, requires registry-declared integrity, writes `tapid.lock`, stores verified package trees, and activates managed `node_modules`. Dependency lifecycle scripts stay disabled.

An explicit `--allow-unverified-registry-artifacts` compatibility exception can accept locally computed artifact integrity for an online install. It emits a warning, cannot be combined with `--offline` or `--frozen`, and produces provenance that frozen replay rejects. See [the install command](/docs/commands/install/) before using it.

Run `tapid install` in an existing project to resolve its declared dependencies. Once the lockfile and verified store are present, replay the same graph without changing the lockfile:

```bash
tapid install --offline --frozen
```

## What the current client can answer

- Which exact package versions and dependency edges were selected?
- Did registry metadata declare the integrity used to authenticate each artifact?
- Does the lockfile's manifest and verified store content validate before activation?
- Were managed `node_modules` files created?
- Can an explicit root script run with forwarded arguments?
- Does the child process exit code return to the caller?
- Were dependency lifecycle scripts suppressed during installation?

The default online registry path fails closed when required registry metadata or declared integrity is missing. The explicit compatibility exception is narrower, visible, and not eligible for frozen replay.

## Run a project script

`tapid run <script>` reads a root `package.json` script, runs it in the project directory, prepends the managed `node_modules/.bin` directory to `PATH`, forwards arguments after `--`, and returns the child exit status.

```bash
tapid run dev
tapid run test -- --runInBand
```

Root scripts can execute arbitrary project code through the platform shell. This is compatibility-oriented process execution, not a sandbox.
