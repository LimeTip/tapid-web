Tapid is a JavaScript and TypeScript package manager written in Rust. Version 0.0.7 can resolve and install a deliberately limited npm-compatible dependency graph. It is not yet a drop-in replacement for npm or pnpm.

## Install Tapid

On macOS or Linux:

```bash
curl -fsSL https://tapid.dev/install.sh | bash
```

On Windows PowerShell:

```powershell
iwr -useb https://tapid.dev/install.ps1 | iex
```

The installer selects the latest stable release, verifies its signed release manifest, checks the archive hash and size, validates the archive structure, and installs the Tapid binary under your user account.

## Install a package

Create a project and install a package from npm:

```bash
tapid init demo
cd demo
tapid install is-char
```

The current command writes the dependency to `package.json`, resolves supported transitive dependencies, verifies registry-declared integrity, writes `tapid.lock`, stores verified package trees, and activates managed `node_modules`. Dependency lifecycle scripts stay disabled.

Run `tapid install` in an existing project to resolve its declared dependencies. Once the lockfile and verified store are present, replay the same graph without changing the lockfile:

```bash
tapid install --frozen
```

## What the current client can answer

- Which exact package versions and dependency edges were selected?
- Did registry metadata declare the integrity used to authenticate each artifact?
- Does the lockfile's manifest and store content validate before activation?
- Were managed `node_modules` files created?
- Can an explicit root script run with forwarded arguments?
- Does the child process exit code return to the caller?
- Were dependency lifecycle scripts suppressed during install?

The online registry path remains constrained. Tapid requires enough registry metadata and integrity information to construct a verified graph, and fails closed when those requirements are not met.

## Run a project script

`tapid run <script>` reads a root `package.json` script, runs it in the project directory, prepends the managed `node_modules/.bin` directory to `PATH`, forwards arguments after `--`, and returns the child exit status.

```bash
tapid run dev
tapid run test -- --runInBand
```

Root scripts can execute arbitrary project code through the platform shell. This is compatibility-oriented process execution, not a sandbox.

## Current status and direction

| Area | Status | What is true today |
| --- | --- | --- |
| Manifest validation | Implemented | `package.json` identity is validated before project work. |
| Lockfile replay | Implemented | Offline and frozen replay require the lockfile and verified store inputs. |
| Node-compatible linking | Implemented | Managed package files and executable metadata are materialized for the supported path. |
| Root scripts | Implemented with constraints | Explicit `tapid run` works, but it is not sandboxed. |
| Package-spec installation | Implemented with constraints | `tapid install is-char` and `tapid i is-char` add and install supported npm packages. |
| Full npm compatibility | In progress | Tags, aliases, peers, workspaces, private registry authentication, and several semver and optional-dependency behaviors remain incomplete. |
| Registry publishing and policy | Future direction | Registry services, provenance verification, policy enforcement, and agent integration are not current client guarantees. |
