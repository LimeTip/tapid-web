# Agent-safe commands

The current Tapid client does not provide an agent runner or command execution service. This page describes the context an eventual agent integration should require, while documenting the safeguards already present in the CLI's explicit `run` command.

## What exists today

`tapid run <script>` runs a root `package.json` script only after the caller chooses that command. It executes in the project directory, prepends the managed `node_modules/.bin` directory to `PATH`, forwards arguments after `--`, and returns the child exit status.

```bash
tapid run --project-dir ./example test -- --runInBand
```

Root scripts may execute arbitrary project code through the platform shell. This is compatibility-oriented process execution, not a sandbox or a security boundary.

## Context an agent should receive

Before an agent starts a package-backed operation, the integration should provide:

- The exact package identity and artifact digest.
- The selected registry and publisher context.
- Release changes and available provenance.
- Declared, inspected, and observed capability signals.
- The policy outcome for this specific operation.
- Whether the artifact is exact or still requires resolution.
- The limitations of the evidence and the enforcement boundary.

This lets an agent distinguish a known operation from one that needs review. It also gives the agent a reason to stop when the release changes or the requested action falls outside its allowed context.

## Planned unattended behavior

Fail-closed behavior is planned for unattended operation. If Tapid cannot establish package identity, gather required evidence, or obtain an allow decision, the operation should stop rather than continue with missing context.

That behavior is a design target, not a current agent integration. Do not describe it as an existing guarantee.
