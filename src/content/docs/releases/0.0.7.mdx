tapid 0.0.7 is the current source-built development target. It connects the consumer path to supported npm registry metadata and artifacts, resolves supported transitive dependencies deterministically, requires registry-declared SHA-512 integrity by default, writes a schema-6 `tapid.lock`, stores verified trees, and materializes managed `node_modules` without running dependency lifecycle scripts.

No asset-backed stable release is currently available. Production support is not available.

## Evaluate the source-built alpha

Follow [Getting started](/docs/getting-started/) to build the current main branch from source. After installation, the shortest supported package path is:

```text
mkdir demo
cd demo
tapid init
tapid i is-char
```

## Lockfile migration

Schema 5 lockfiles must be regenerated online because schema 6 records whether package integrity came from registry metadata. Schema 4 remains a controlled compatibility path with narrower identity and replay rules.

```text
tapid install
tapid lock verify
```

## Current limits

tapid implements an npm-compatible subset rather than complete npm behavior. Tags, aliases, peer resolution, workspaces, private-registry authentication, lifecycle-script approval, and several package-management commands remain incomplete. Dependency lifecycle scripts stay disabled by default.

The public installer endpoints cannot complete their no-argument stable path until signed release metadata and all advertised platform archives are published and clean release exercises pass.

See the canonical [repository release notes](https://github.com/LimeTip/tapid/blob/main/docs/releases/0.0.7.md) for complete implementation details.
