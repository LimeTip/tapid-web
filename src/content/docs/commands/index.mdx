Tapid's CLI is intentionally explicit. Each command has a narrow responsibility, documented inputs, and a clear boundary when the current client cannot complete an operation.

## Command reference

- [`tapid init`](/docs/commands/init/) creates a private `package.json` without overwriting an existing file.
- [`tapid manifest validate`](/docs/commands/manifest-validate/) validates a selected manifest before project work.
- [`tapid lock verify`](/docs/commands/lock-verify/) validates the lockfile in the current project.
- [`tapid install`](/docs/commands/install/) replays or installs project dependencies through the currently supported paths.
- [`tapid run`](/docs/commands/run/) runs an explicit root `package.json` script and forwards arguments.
- [`tapid upgrade`](/docs/commands/upgrade/) inspects and applies a verified stable Tapid release.

## Status language

Each page labels behavior as **implemented**, **constrained**, or **not currently supported**. A command can be implemented while still having important limits. Examples stay within the behavior verified for the current release.

## Typical project path

Install the latest stable binary, create a project, and install a package:

```bash
curl -fsSL https://tapid.dev/install.sh | bash
tapid init demo
cd demo
tapid install is-char
tapid install --frozen
```

Tapid 0.0.7 supports a bounded npm-compatible subset. Read the install command page before migrating a project that depends on tags, aliases, peers, workspaces, private registries, lifecycle scripts, or other npm-specific behavior.
